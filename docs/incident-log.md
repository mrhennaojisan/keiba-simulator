# 障害・運用ログ

## 2026-11 APIが500を返す（`AttributeError: PAGE_MODES`）
- **症状**: 画面に「取得できませんでした」。APIが `internal error`（500）
- **検知**: ブラウザの開発者ツールで500を確認。CloudWatch Logs（ApiFn）に `AttributeError ... 'PAGE_MODES'`
- **原因**: 新しい `handlers.py`（`PAGE_MODES`を参照）と、古い `keiba_core.py` が混在したLambdaをデプロイした。古いzipから素材を作っていた（手作業のビルドの取り違え）
- **対処**: 最新のコードで素材を作り直し、`PAGE_MODES` が含まれることとファイルサイズを確認して再デプロイ
- **再発防止**:
  - ビルドとデプロイをGitHub Actionsに統一（`deploy.yml`。毎回その場でビルド）
  - デプロイ前に `PAGE_MODES` の存在を検査するステップを追加
  - Lambdaエラー・API 5xxのアラームでメール通知（CDKで定義）

## 2026-11 デプロイ手順のつまずき（Windows）
- `--app is required`: `cdk` を `cdk.json` のないフォルダで実行 → プロジェクト直下で実行する
- zip展開で二重フォルダになり、`requirements.txt` が見つからない → 展開先を確認する
- **再発防止**: READMEに「実行するフォルダ」を明記。CIでの自動デプロイで手元環境への依存を減らす

## 2026-11 画面に古い項目が残る
- **症状**: コードから削除した項目が、保存済みの画面に表示され続けた
- **原因**: 画面HTMLを事前計算してDynamoDBに保存する設計のため、コード更新後も保存済みの出力は旧版
- **対処**: 再計算が走るまで待つ（STALE_SECで自動再計算）か、`refresh` を手動実行
- **改善案**: 保存するページにバージョンを持たせ、コード更新時に旧版を無効化する
